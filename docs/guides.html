Guides

Web accessibility guides

Short, practical guides for developers who want to ship accessible pages: what each rule means, who it helps and the exact code to fix it.

  • A website accessibility checker that explains every fixCheck any website for WCAG 2.2 accessibility problems in the browser, the terminal or your tests, with a plain language explanation and the exact fix for each.
  • How to fix color contrast without losing your brandLearn the WCAG contrast ratios (4.5:1, 3:1 and 7:1), find failing text automatically, and fix it with the closest passing color that keeps your brand hue.
  • Alt text best practices, with examples for every kind of imageWrite alt text that helps: when to describe and when to leave alt empty, images in links and buttons, icons, charts and SVG, with before and after examples.
  • Accessible form labels: how to label every field rightLabel every form field the accessible way: visible labels, fieldset and legend, hints and errors with aria-describedby, autocomplete and paste friendly logins.
  • WCAG 2.2 checklist for developersA practical WCAG 2.2 checklist for levels A and AA: what changed from 2.1, the six new criteria, and which items a tool can check and which need a human.
  • Accessibility testing in CIAdd accessibility testing to CI: fail builds on serious issues, get GitHub Actions annotations and a job summary, and test components with Vitest or Jest.
  • aria-label vs aria-labelledby: which one to use and whenaria-label vs aria-labelledby explained with examples: how accessible names are computed, when each attribute fits, and the mistakes screen readers ignore.
  • Accessibility overlay vs real fixes: what actually worksAccessibility overlay vs real fixes: what runtime widgets can and cannot repair, why source fixes last longer, and how a diagnostic overlay fits a dev workflow.
  • WCAG 2.2 cheat sheet in plain languageEvery A and AA success criterion in one or two sentences, with the a11ymedic rules that check it.
