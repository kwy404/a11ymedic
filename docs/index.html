How it works

Exam, diagnosis, treatment

Three steps, the same everywhere: in this page, on any site, in the terminal, in CI and in your tests.

  1. 1 Exam

    <button><svg></button>

    61 rules run on a real page. In the browser a11ymedic reads the real colors and sizes; on Node it parses your HTML and applies your CSS itself.

  2. 2 Diagnosis

    1Button has no nameScreen readers say only "button".

    Each problem says what is wrong with this exact element, why it matters, who it hurts and which WCAG 2.2 rule it breaks, in English and Portuguese.

  3. 3 Treatment

    <button aria-label="Search"><svg></button>

    Every finding comes with the patched code. Safe fixes apply in one command with a diff preview; the rest come ready to paste and review.

Who it is for

Every diagnosis names who it hurts

A finding is not a lint warning. Each one says which people hit the barrier, so you know why the fix matters before you write it.

  • Screen reader usersHear the page read aloud and move by headings, links and landmarks.
  • Low visionZoom to 200 percent and beyond, and need strong contrast to read.
  • Color blindnessCannot tell some colors apart, so color alone says nothing.
  • Keyboard onlyTab, Enter and arrows instead of a mouse, so focus must show.
  • Cognitive and learningNeed clear labels, steady layouts and time to read.
  • Motor and dexterityTremors or a switch device make tiny targets and drags hard.
  • Deaf and hard of hearingRely on captions and transcripts for anything spoken.

Quick start

Four ways to call the medic

Same rules, same explanations and the same fixes wherever you run it.

House call

On any page: script tag or bookmarklet

Add one script tag in development. Numbered pins mark each problem and a keyboard accessible side panel explains it, with the health score, how it changed since your last check and a print friendly report. Alt + Shift + A toggles it.

Or drag this bookmarklet to your bookmarks bar and press it on any site: a11ymedic check-up

Walk-in clinic

Command line: files, globs and URLs

Check built HTML, a folder or a live URL. With Playwright or Puppeteer installed, URLs are checked in a headless browser; without them the HTML is fetched and checked statically.

Daily rounds

CI: fail the build on serious problems

On GitHub Actions a11ymedic prints annotations on the changed lines and writes a job summary on its own.

Lab tests

Tests: Vitest and Jest

Audit rendered components and get a readable failure with the fix for each problem.

API

A small API for scripts and tests

Main functions
FunctionWhat it does
audit(html | document | element, options?)Runs the rules. Returns findings (most severe first), human checks and counts.
auditDocument(root, options?)The same, synchronous, for a live DOM.
fixHtml(html, options?)Applies safe fixes to source text and keeps formatting. Idempotent.
applyFix(finding)Applies one fix to the live DOM.
contrastRatio(fg, bg), suggestColors(fg, bg, { ratio })WCAG contrast and the closest passing pair in OKLCH.
accessibleName(el), getRole(el)Accessible name and role, as assistive technology sees them.
formatText, toJSON, toMarkdown, toHtml, githubAnnotations, githubSummaryReports.
score(result), recordScore(key, result)The 0 to 100 health score, and a score history kept in localStorage.
bookmarklet({ lang })The bookmarklet URL.
overlay(options?), printReport(result)Browser build only: the pins and panel, and the print friendly report.

FAQ

Questions people ask the medic

Is a11ymedic free?

Yes. It is open source under the MIT license. The checks run in your browser, on your machine or in your CI; there is no a11ymedic server and nothing to sign up for.

How do I check a page that is already online?

Type its address in the box at the top of this page. If the site does not let other pages read it, run npx a11ymedic https://your-site.com in a terminal, or press the bookmarklet on the page to see numbered pins on it.

Can it fix problems automatically?

It fixes the safe ones: a11ymedic fix "src/**/*.html" shows a diff and --write applies it. Safe fixes are things like an empty alt on a spacer image, tabindex 0 instead of 5, re-enabling zoom or a misspelled ARIA attribute. Anything that needs a human decision, such as alt text for a photo or a label text, comes as a suggestion to review.

Does it replace testing with real people?

No. Automated checks catch many common problems, but not all of them: whether alt text is accurate, whether a flow makes sense with a screen reader or whether captions are correct still need people. a11ymedic lists what it cannot decide as a human check.

Does it work with React, Vue, Angular and Next.js?

Yes. Test rendered components with expect(await audit(container)).toHaveNoViolations() in Vitest or Jest, check built HTML with the CLI, or load the overlay script in development.

Does the overlay change my site for visitors?

No. The overlay is a diagnosis tool for the people who build the site: it highlights problems and shows the fix. Real fixes belong in your source code.
