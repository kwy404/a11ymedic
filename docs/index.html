How it works

Exam, diagnosis, treatment

  1. 1. Exam

    An engine written from scratch runs 61 rules on a real DOM. In the browser it reads computed styles and real boxes. On Node it parses HTML with jsdom, cascades your CSS itself (specificity, variables, inheritance) and keeps line numbers.

  2. 2. Diagnosis

    Every finding says what is wrong with this exact element, why it matters, who is affected and which WCAG 2.2 criterion it breaks, in English and Portuguese, with the selector and the HTML snippet.

  3. 3. Treatment

    Each finding comes with patched code: the missing alt, aria-label or label for, a contrast safe color picked in OKLCH. Safe fixes apply in one command with a diff preview, and they are idempotent.

Quick start

Four ways to call the medic

On any page: script tag or bookmarklet

Add one script tag in development. Numbered pins mark each problem and a keyboard accessible side panel explains it. Alt + Shift + A toggles it.

Or drag this bookmarklet to your bookmarks bar and press it on any site: a11ymedic check-up

Command line: files, globs and URLs

Check built HTML, a folder or a live URL. With Playwright or Puppeteer installed, URLs are checked in a headless browser; without them the HTML is fetched and checked statically.

CI: fail the build on serious problems

On GitHub Actions a11ymedic prints annotations on the changed lines and writes a job summary on its own.

Tests: Vitest and Jest

Audit rendered components and get a readable failure with the fix for each problem.

FAQ

Questions people ask the medic

What is the best free website accessibility checker?

Use one that finds problems and tells you how to fix them. a11ymedic is free and open source: it checks 61 WCAG 2.2 rules in the browser, on the command line and in CI, explains each problem in plain English or Portuguese and gives the patched HTML for every finding.

How do I check a website for accessibility problems?

Run npx a11ymedic https://your-site.com for a full report, or add the a11ymedic script tag (or the bookmarklet) to see numbered pins on the page itself. For your own code, run npx a11ymedic "src/**/*.html" and add --fail-on serious in CI.

Can a11ymedic fix accessibility issues automatically?

It fixes the safe ones: a11ymedic fix "src/**/*.html" shows a diff and --write applies it. Safe fixes are things like an empty alt on a spacer image, tabindex 0 instead of 5, re-enabling zoom or a misspelled ARIA attribute. Everything that needs a human decision (alt text that describes a photo, a label text) comes as a ready to paste suggestion instead.

Does a11ymedic replace testing with real users?

No. Automated checks catch a large share of common problems, but not all of them: whether alt text is accurate, whether a flow makes sense with a screen reader or whether captions are correct still need people. a11ymedic marks what it cannot decide as a human check.

Does it work with React, Vue, Angular and Next.js?

Yes. Test rendered components with expect(await audit(container)).toHaveNoViolations() in Vitest or Jest, check built HTML with the CLI, or load the overlay script in development.

Is a11ymedic an accessibility overlay?

No. Its overlay is a diagnosis tool for the people who build the site: it highlights problems and shows the fix. It never changes the page for visitors. Real fixes belong in your source code.
